## 1. Governing rule

Software capability and permission to capture, process, store, redistribute, or publish data are separate questions. The project MUST NOT infer permission from technical accessibility. Unknown material rights block the proposed source or asset until qualified review resolves them.

S2XYZ-CODEX-003 is stricter than the Charter's possible future source classes: only locally generated synthetic values, self-rendered text, and locally generated screenshots are allowed in this run.

## 2. Allowed data in this run

- Fixed-seed synthetic coordinate and elevation values generated by repository code.
- Text rendered locally from those synthetic values using an OS-provided font that is not copied into the repository.
- PNG screenshots generated locally from the synthetic text layout.
- Actual raw OCR output derived from those generated PNG files.
- Parsed, accepted, rejected, metrics, test, and environment evidence derived only from the registered fixture.
- Sanitized tool and dependency identity evidence necessary to reproduce the private lab.

Every fixture set and derived evidence family MUST be registered. Generated status does not create public-release authorization; the repository remains private and no repository licence is selected.

## 3. Prohibited data and conduct

The run MUST NOT:

- open, name, target, imitate, or automate a third-party mapping or elevation service;
- use a service-specific profile, preset, screen coordinate, interface asset, URL, DOM, API, network trace, application memory, or backend extraction;
- use real third-party, client, employer, personal, confidential, proprietary, survey, LiDAR, mapping, or elevation data;
- add copied interface assets, real screenshots, public demonstration datasets, or extracted third-party readings;
- bypass CAPTCHA, rate limits, authentication, access controls, robots controls, technical protections, or terms enforcement;
- conceal automation or represent synthetic evaluation as live-source capture;
- upload images or text to a cloud OCR or telemetry service;
- redistribute an OS font, OCR model, binary, dataset, or other component without documented authority;
- select a repository licence or publish the repository;
- claim survey, authoritative, production, construction, earthwork, universal-compatibility, or Kubla import suitability.

## 5. Dataset and asset registration

Before a fixture or derived artifact is committed, the Dataset and Licence Register MUST record its stable ID/version, scenario coverage, relative paths, hashes when available, origin, fixed seed/configuration, external-source status, real/personal/confidential/proprietary-data flags, named-service dependency, rights/licence evidence, permitted use, redistribution status, retention, and review disposition.

Required classifications for this run are:

- origin: `locally generated synthetic project data`;
- external source: `none`;
- contains real data: `false`;
- contains personal/confidential/proprietary data: `false`;
- named-service dependency: `none`;
- allowed use: `private internal S2XYZ-CODEX-003 evaluation only`;
- public redistribution: `not authorized`.

## 6. Dependency and asset controls

The Dependency and Licence Register MUST cover runtime interpreters, shells, system frameworks, OCR APIs/language capabilities, rendering APIs, fonts, direct/transitive packages, native executables/DLLs, models, and downloaded assets. Each row records exact version evidence, source, purpose, licence identifier or explicit unresolved status, evidence location, whether it is redistributed, network/telemetry behavior, concern, and disposition.

Finding a licence identifier is not legal approval. No dependency, font, model, or binary may be copied into Git without confirmed authority. Global package inventories are not project dependency inventories.

## 7. Privacy and minimum evidence

Repository evidence uses an allowlist. It MAY include OS version/build, architecture, selected runtime and shell versions, local OCR engine identity/version evidence, locale, rendering scale/font family and size, relative paths, hashes, durations, test results, and task/commit identifiers.

It MUST NOT include usernames, hostnames, domain names, absolute home/repository paths, IP/MAC addresses, hardware serials, environment-variable dumps, tokens, credentials, private-index URLs, unrelated global packages, browser state, notification content, or unrelated application data.

Raw OCR is treated as untrusted text. CSV and logs must quote it safely, reject control characters for parsing, prevent formula interpretation, avoid shell interpolation, and retain sanitized error codes rather than secret-bearing stack or environment dumps.

## 8. Retention, deletion, and copy-on-write

- Registered, sanitized synthetic screenshots, raw OCR, outputs, metrics, test results, review records, and manifests are retained copy-on-write in Git as run evidence.
- Prior run evidence MUST NOT be deleted, overwritten, or silently regenerated.
- `.venv`, caches, bytecode, temporary files, installer artifacts, and non-retained probe images remain untracked and may be removed after verification.
- Full-desktop or real-source captures are prohibited from Git and are not required evidence.
- Unexpected real/personal/confidential/proprietary content is quarantined outside Git, the run stops, and the project owner is notified. It is not copied into an issue, PR, log, or chat response.
- Accidental sensitive Git history is an incident requiring escalation; agents MUST NOT rewrite shared history unilaterally.

## 9. Optional live-region smoke-test boundary

Live capture is not required. If attempted, it MUST show only the local synthetic fixture in a visible user-controlled interactive session, crop only the declared synthetic region, exclude window chrome/background applications/notifications, avoid full-desktop retention, remove metadata or pass an explicit allowlist inspection proving no disallowed metadata remains, and pass visual pre-commit review. If any condition is unavailable, status is exactly `Not executed`.

No result from generated-image testing may be described as live capture.

## 10. Contamination and incident response

If unexpected real, service-specific, personal, employer, client, confidential, proprietary, credential, or sensitive-location data appears in a value, image, OCR text, log, path, metadata, test output, commit, or proposed PR:

1. Stop processing and do not stage, commit, push, or paste the content.
2. Keep the affected artifact outside Git and minimize further copies.
3. Record only a non-sensitive incident identifier and high-level category.
4. Notify the project owner for disposition and, where appropriate, qualified privacy/security/legal review.
5. Resume only with a clean synthetic regeneration and recorded authorization.

## 11. Claims and demonstration language

Every report, README, example, demonstration-export metadata, and public-facing draft created in this run MUST state exactly:

`Conceptual and preliminary estimating data only.`

The run MUST state generated screenshots were tested, not live capture. The source-coordinate XYZ demonstration contains geographic degrees and is not proven Kubla-ready or suitable for import. No output is authoritative or survey-grade.

## 12. Gate G2 readiness

G2 is ready for a parent decision only when this document, the Dataset and Licence Register, Privacy and Threat Review, and Risk Register exist; every planned fixture is registered synthetic; retention, redaction, incident, live-capture, claims, and source-permission controls are operational; a read-only guardrails reviewer has assessed them; and all Blocker/Major findings are resolved. The reviewer does not approve the gate.
